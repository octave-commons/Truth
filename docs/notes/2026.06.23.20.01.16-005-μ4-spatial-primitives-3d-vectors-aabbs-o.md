## μ4 – Spatial primitives (3D vectors, AABBs, octants, bodies)

**Goal:** lock in the basic spatial vocabulary in `shape.spatial` so all higher layers talk the same language.

```clojure
(ns shape.spatial-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.spatial :as spatial]))

;; μ4.0: 3D vector operations behave as expected.
(deftest vec3-ops
  (testing "Basic vec3 arithmetic and norms"
    (let [a (spatial/vec3 1.0 2.0 3.0)
          b (spatial/vec3 -1.0 0.0 4.0)]
      (is (= [1.0 2.0 3.0] a))
      (is (= [0.0 2.0 7.0] (spatial/v+ a b)))
      (is (= [2.0 4.0 6.0] (spatial/v* a 2.0)))
      (is (<= (Math/abs (- (spatial/len a)
                           (Math/sqrt 14.0)))
              1.0e-9))
      (is (= 0.0 (spatial/len (spatial/vec3 0.0 0.0 0.0)))))))

;; μ4.1: Axis-aligned bounding boxes (AABB) contain points and can be expanded.
(deftest aabb-contains-and-expand
  (testing "AABB containment and expansion around points"
    (let [p1 (spatial/vec3 -1.0 0.0 2.0)
          p2 (spatial/vec3  3.0 5.0 -2.0)
          bb (spatial/aabb-from-points [p1 p2])]
      (is (spatial/contains? bb p1))
      (is (spatial/contains? bb p2))
      ;; Center lies inside.
      (is (spatial/contains? bb (spatial/center bb)))
      ;; Expanding by a point grows the box or keeps it the same.
      (let [bb2 (spatial/aabb-include bb (spatial/vec3 10.0 0.0 0.0))]
        (is (spatial/contains? bb2 (spatial/vec3 10.0 0.0 0.0)))
        (is (spatial/contains? bb2 p1))
        (is (spatial/contains? bb2 p2))))))

;; μ4.2: Octant classification for an AABB center works as expected.
(deftest octant-classification
  (testing "Points are correctly assigned to AABB octants"
    (let [bb    (spatial/aabb (spatial/vec3 -1.0 -1.0 -1.0)
                              (spatial/vec3  1.0  1.0  1.0))
          center (spatial/center bb)]
      ;; Center can be treated specially (e.g. pick one octant deterministically)
      (is (spatial/octant bb center))
      ;; A few representative points:
      (is (= :octant/ppp (spatial/octant bb (spatial/vec3 0.5 0.5 0.5))))   ;; +x +y +z
      (is (= :octant/ppm (spatial/octant bb (spatial/vec3 0.5 0.5 -0.5))))  ;; +x +y -z
      (is (= :octant/mpm (spatial/octant bb (spatial/vec3 -0.5 0.5 -0.5)))) ;; -x +y -z
      (is (= :octant/mmm (spatial/octant bb (spatial/vec3 -0.5 -0.5 -0.5)))))))

;; μ4.3: Body shape packs mass, radius, and kind.
(deftest body-shape
  (testing "Bodies have mass, radius, position, velocity, and kind"
    (let [b (spatial/->body
              {:id       1
               :mass     5.972e24
               :radius   6.371e6
               :kind     :body/planet
               :position (spatial/vec3 0.0 0.0 0.0)
               :velocity (spatial/vec3 0.0 0.0 0.0)})]
      (is (= 1 (:id b)))
      (is (= :body/planet (:kind b)))
      (is (= 5.972e24 (:mass b)))
      (is (= 6.371e6 (:radius b)))
      (is (= [0.0 0.0 0.0] (:position b)))
      (is (= [0.0 0.0 0.0] (:velocity b))))))
```

Implementation sketch for `shape.spatial`:

- `vec3`, `v+`, `v-`, `v*`, `len`, `dist`.
- `aabb` record with `min` and `max`, `contains?`, `center`, `aabb-from-points`, `aabb-include`.
- `octant` that maps a point relative to an AABB center into one of 8 keywords (e.g. `:octant/ppp` etc.).
- `Body` record (`id`, `mass`, `radius`, `kind`, `position`, `velocity`).

Barnes–Hut 3D implementations in other engines use exactly this combination: 3D vectors + octree built from an AABB root.[^7_5][^7_3][^7_4][^7_1]

## μ5 – Barnes–Hut octree: build and approximate forces

Now we give the gravity domain its own categorical home, `domain.gravity.barnes-hut`, expressed in terms of our spatial primitives. Barnes–Hut in 3D:

- Represents space as an octree; each internal node stores COM and total mass.[^7_2][^7_4][^7_1][^7_5]
- For a given body, we either:
    - approximate a distant node as a single mass if $s/d < \theta$, or
    - recurse into the node’s children.[^7_3][^7_4][^7_1][^7_2]


### μ5 specs

```clojure
(ns domain.gravity.barnes-hut-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.spatial :as spatial]
    [domain.gravity.barnes-hut :as bh]))

;; Gravitational constant we'll use in tests (SI units but values small).
(def ^:const G 6.67408e-11)

;; μ5.0: Tree construction covers all bodies and computes COM and total mass.
(deftest build-octree-basic
  (testing "Octree root encloses all bodies and internal nodes store COM + mass"
    (let [bodies [(spatial/->body
                    {:id       1
                     :mass     1.0
                     :radius   1.0
                     :kind     :body/test
                     :position (spatial/vec3 -1.0 0.0 0.0)
                     :velocity (spatial/vec3 0.0 0.0 0.0)})
                  (spatial/->body
                    {:id       2
                     :mass     3.0
                     :radius   1.0
                     :kind     :body/test
                     :position (spatial/vec3 2.0 0.0 0.0)
                     :velocity (spatial/vec3 0.0 0.0 0.0)})]
          tree   (bh/build-tree bodies)]
      (is (bh/internal-node? tree))
      ;; Root AABB contains both bodies.
      (doseq [b bodies]
        (is (spatial/contains? (:aabb tree) (:position b))))
      ;; Total mass and center of mass.
      (is (= 4.0 (:mass tree)))
      (let [[cx _ _] (:com tree)]
        ;; COM along x = (1* -1 + 3*2)/4 = ( -1 + 6 ) / 4 = 5/4 = 1.25
        (is (<= (Math/abs (- cx 1.25)) 1.0e-9))))))

;; μ5.1: Force from a single body matches the Barnes–Hut approximation when θ is small.
(deftest single-body-force
  (testing "With one other body, BH force matches direct Newtonian force"
    (let [sun  (spatial/->body
                 {:id       1
                  :mass     1.0e6
                  :radius   1.0
                  :kind     :body/star
                  :position (spatial/vec3 0.0 0.0 0.0)
                  :velocity (spatial/vec3 0.0 0.0 0.0)})
          earth (spatial/->body
                  {:id       2
                   :mass     1.0
                   :radius   1.0
                   :kind     :body/planet
                   :position (spatial/vec3 10.0 0.0 0.0)
                   :velocity (spatial/vec3 0.0 0.0 0.0)})
          tree  (bh/build-tree [sun earth])
          θ     0.1
          acc   (bh/acceleration G θ tree earth)
          ;; Direct Newton: a = G * M / r^2 along -x.
          r     10.0
          a-mag (/ (* G (:mass sun)) (* r r))
          expected (spatial/vec3 (- a-mag) 0.0 0.0)]
      (is (<= (spatial/dist acc expected) 1.0e-9)))))

;; μ5.2: For a symmetric configuration, net acceleration is ~0.
(deftest symmetric-cancelation
  (testing "Equal masses symmetrically arranged around a center have ~0 net acceleration"
    (let [b1 (spatial/->body {:id 1 :mass 1.0 :radius 1.0 :kind :body/test
                              :position (spatial/vec3 -1.0 0.0 0.0)
                              :velocity (spatial/vec3 0.0 0.0 0.0)})
          b2 (spatial/->body {:id 2 :mass 1.0 :radius 1.0 :kind :body/test
                              :position (spatial/vec3  1.0 0.0 0.0)
                              :velocity (spatial/vec3 0.0 0.0 0.0)})
          center (spatial/->body {:id 3 :mass 1.0 :radius 1.0 :kind :body/test
                                  :position (spatial/vec3 0.0 0.0 0.0)
                                  :velocity (spatial/vec3 0.0 0.0 0.0)})
          tree (bh/build-tree [b1 b2 center])
          θ   0.5
          acc (bh/acceleration G θ tree center)]
      (is (<= (spatial/len acc) 1.0e-6)))))
```

Implementation outline for `domain.gravity.barnes-hut`:

- `build-tree`:
    - Compute bounding AABB enclosing all bodies.
    - If 0 bodies ⇒ empty node.
    - If 1 body ⇒ leaf node `{ :type :leaf, :body b, :aabb bb, :mass m, :com position }`.
    - Else:
        - Subdivide AABB into 8 octants.
        - Partition bodies into octants via `spatial/octant`.
        - Recursively build child nodes.
        - Compute `:mass` and `:com` for the internal node by folding children.[^7_4][^7_1][^7_5][^7_3]
- `acceleration G θ tree body`:
    - Recurse `acc-from-node tree body`.
    - For each internal node:
        - Let `s` be node AABB size (width), `d` distance from body to node COM.
        - If `s / d < θ`, approximate whole node as single body at COM: $a = G M / d^2$ along direction from body to COM.[^7_1][^7_2][^7_3][^7_4]
        - Else, recurse into children.
    - For a leaf with one body that isn’t `body` itself, compute exact Newtonian contribution with softening if desired.

This replicates your 2D quadtree setup, but with 3D octree semantics.

## μ6 – Gravity ECS system with star/planet/person roles

Now we tie this into the ECS skeleton (`domain.system`) so that:

- Bodies live as components (`:component/body`) keyed by entity‑id.
- Each tick:
    - Build Barnes–Hut tree from all bodies.
    - Compute acceleration for each body (potentially in parallel).
    - Integrate velocities/positions.
- “Special people rule”: when a `:body/person` is within a certain radius of Earth, switch from BH approximation to direct pairwise Earth–person acceleration (F=ma).


### μ6 specs

```clojure
(ns domain.gravity.system-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.spatial :as spatial]
    [domain.gravity.barnes-hut :as bh]
    [domain.system :as sys]
    [law.contract :as contract]
    [law.ledger :as ledger]))

(def ^:const G 6.67408e-11)

(defn demo-gravity-system []
  (let [body-shape   {:id       int?
                      :mass     number?
                      :radius   number?
                      :kind     keyword?
                      :position vector?
                      :velocity vector?}
        body-contract (contract/->contract
                        {:id       (shape.core/new-resource-id)
                         :shape-id (shape.core/new-shape-id)
                         :kind     :type
                         :schema   body-shape
                         :name     "body-component"})
        tick-contract (contract/->contract
                        {:id       (shape.core/new-resource-id)
                         :shape-id (shape.core/new-shape-id)
                         :kind     :type
                         :schema   {:tick int?}
                         :name     "gravity-tick"})
        store         (sys/->component-store
                        {:resource-type :component/body
                         :window        2
                         :gap           1})
        ;; update-fn will be provided by domain.gravity.system
        ]
    {:body-contract body-contract
     :tick-contract tick-contract
     :store         store}))

;; μ6.0: single planet orbiting star has expected direction of acceleration.
(deftest star-planet-acc-direction
  (testing "Earth-like body accelerates towards a massive sun"
    (let [{:keys [body-contract tick-contract store]} (demo-gravity-system)
          ;; Build a system with gravity update-fn
          gravity-update-fn (domain.gravity.system/make-update-fn G)
          sys (sys/->system
                {:id                 :system/gravity
                 :component-store    store
                 :component-contract body-contract
                 :tick-contract      tick-contract
                 :watched-event-kinds [:component/body-initialised]
                 :event-queue        []
                 :update-fn          gravity-update-fn})
          ;; Seed a snapshot with sun and earth components.
          sun-entity   1
          earth-entity 2
          sun-body   (spatial/->body
                       {:id       sun-entity
                        :mass     1.0e6
                        :radius   10.0
                        :kind     :body/star
                        :position (spatial/vec3 0.0 0.0 0.0)
                        :velocity (spatial/vec3 0.0 0.0 0.0)})
          earth-body (spatial/->body
                       {:id       earth-entity
                        :mass     1.0
                        :radius   1.0
                        :kind     :body/planet
                        :position (spatial/vec3 100.0 0.0 0.0)
                        :velocity (spatial/vec3 0.0 1.0 0.0)})
          ;; manually install initial snapshot
          store0 (-> store
                     (assoc :last-tick 0)
                     (assoc :history [{:tick 0
                                       :components {sun-entity   {:value sun-body}
                                                    earth-entity {:value earth-body}}}]))
          sys0   (assoc sys :component-store store0)
          led0   (ledger/empty-ledger)
          {sys1 :system led1 :ledger} (sys/tick sys0 led0)
          earth1 (sys/observe sys1 earth-entity 0)
          v0 (:velocity earth-body)
          v1 (:velocity (:value earth1))
          dv (spatial/v- v1 v0)]
      ;; dv should be roughly pointing towards the sun: negative x.
      (is (< (first dv) 0.0))
      ;; dv's magnitude should be > 0.
      (is (> (spatial/len dv) 0.0)))))

;; μ6.1: person near Earth is handled with direct pairwise Newtonian gravity.
(deftest person-near-earth-direct-gravity
  (testing "Person within threshold of Earth uses direct F=ma instead of BH approximation"
    (let [{:keys [body-contract tick-contract store]} (demo-gravity-system)
          gravity-update-fn (domain.gravity.system/make-update-fn G
                                           {:person-direct-threshold 10.0}) ;; meters
          sys (sys/->system
                {:id                 :system/gravity
                 :component-store    store
                 :component-contract body-contract
                 :tick-contract      tick-contract
                 :watched-event-kinds []
                 :event-queue        []
                 :update-fn          gravity-update-fn})
          earth-id 1
          person-id 2
          earth-body (spatial/->body
                       {:id       earth-id
                        :mass     5.972e24
                        :radius   6.371e6
                        :kind     :body/planet
                        :position (spatial/vec3 0.0 0.0 0.0)
                        :velocity (spatial/vec3 0.0 0.0 0.0)})
          ;; Person 5 meters above the surface on +z axis.
          person-pos (spatial/vec3 0.0 0.0 (+ (:radius earth-body) 5.0))
          person-body (spatial/->body
                        {:id       person-id
                         :mass     80.0
                         :radius   0.5
                         :kind     :body/person
                         :position person-pos
                         :velocity (spatial/vec3 0.0 0.0 0.0)})
          store0 (-> store
                     (assoc :last-tick 0)
                     (assoc :history [{:tick 0
                                       :components {earth-id  {:value earth-body}
                                                    person-id {:value person-body}}}]))
          sys0   (assoc sys :component-store store0)
          led0   (ledger/empty-ledger)
          {sys1 :system led1 :ledger} (sys/tick sys0 led0)
          person1 (sys/observe sys1 person-id 0)
          v1 (:velocity (:value person1))]
      ;; Person should have acquired some downward velocity (towards Earth center).
      (is (< (nth v1 2) 0.0)))))
```

Implementation idea for `domain.gravity.system/make-update-fn`:

- Given `G` and options, returns `(fn [system entity-id {:keys [value]}] new-component)`.

Within that function:

1. Read the **latest snapshot** from `system`’s `component-store` and pull out all bodies.
2. Build BH tree from those bodies.
3. For each entity:
    - For bodies of kind `:body/person`, check distance to Earth (maybe via a `:body/planet` with `:tag :earth`). If within `person-direct-threshold`, compute acceleration from Earth directly using $a = G M / r^2$ along radial direction, ignoring other bodies for that step.
    - Otherwise, compute acceleration using `bh/acceleration`.
4. Integrate velocity and position with a fixed timestep `dt` (configurable).
5. Return new component record `{:value updated-body}`.

All of that is pure: the system is just a function from “old snapshot + dt” to “new snapshot”.

## μ7 – Multi-threaded evaluation spec (determinism under parallelism)

Your JS workers already partitioned work spatially for safe multithreading. In this Clojure version, the simplest safe parallelism is:

- Build the BH tree once (single thread).
- Partition bodies into chunks.
- For each chunk, compute accelerations using the shared, immutable tree, then integrate.
- Combine chunk results into a new components map.

Because the tree and bodies are immutable inputs and each body’s update is independent given the tree, you get deterministic results whether you run sequentially or in parallel, as long as you avoid nondeterministic floating‑point reduction order.

μ‑spec:

```clojure
(ns domain.gravity.parallel-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.spatial :as spatial]
    [domain.gravity.barnes-hut :as bh]
    [domain.gravity.parallel :as gp]))

(def ^:const G 6.67408e-11)

(defn random-bodies
  [n]
  ;; Deterministic RNG for reproducible test.
  (let [rng (java.util.Random. 42)]
    (vec
      (for [i (range n)]
        (let [x (.nextDouble rng)
              y (.nextDouble rng)
              z (.nextDouble rng)]
          (spatial/->body
            {:id       i
             :mass     1.0
             :radius   1.0
             :kind     :body/test
             :position (spatial/vec3 x y z)
             :velocity (spatial/vec3 0.0 0.0 0.0)}))))))

;; μ7.0: Parallel update matches sequential update for fixed dt.
(deftest parallel-vs-sequential-update
  (testing "Parallel gravity update yields same results as sequential"
    (let [bodies (random-bodies 1000)
          θ      0.5
          dt     0.01
          ;; Sequential: build tree then update all bodies in one pass.
          seq'   (gp/update-bodies-sequential G θ dt bodies)
          ;; Parallel: same but chunked over multiple workers.
          par'   (gp/update-bodies-parallel   G θ dt bodies {:chunks 8})]
      ;; Compare per-body positions and velocities by id.
      (doseq [[b-seq b-par] (map vector seq' par')]
        (is (= (:id b-seq) (:id b-par)))
        (is (<= (spatial/dist (:position b-seq) (:position b-par)) 1.0e-9))
        (is (<= (spatial/dist (:velocity b-seq) (:velocity b-par)) 1.0e-9))))))
```

Implementation sketch for `domain.gravity.parallel`:

```clojure
(defn update-body
  [G θ dt tree body]
  (let [a   (bh/acceleration G θ tree body)
        v0  (:velocity body)
        p0  (:position body)
        v1  (spatial/v+ v0 (spatial/v* a dt))
        p1  (spatial/v+ p0 (spatial/v* v1 dt))]
    (assoc body
           :velocity v1
           :position p1)))

(defn update-bodies-sequential
  [G θ dt bodies]
  (let [tree (bh/build-tree bodies)]
    (mapv #(update-body G θ dt tree %) bodies)))

(defn update-bodies-parallel
  [G θ dt bodies {:keys [chunks] :or {chunks (.availableProcessors (Runtime/getRuntime))}}]
  (let [tree    (bh/build-tree bodies)
        groups  (partition-all (Math/ceil (/ (count bodies) (double chunks))) bodies)
        ;; Use futures, agents, or your preferred thread pool.
        updated (->> groups
                     (map (fn [chunk]
                            (future
                              (mapv #(update-body G θ dt tree %) chunk))))
                     (map deref)
                     (apply concat))]
    (vec updated)))
```

Because `tree` is shared immutable input and each `update-body` only touches its own body, this parallelization is safe and deterministic (modulo floating‑point, but we’re controlling order at the per‑body level).

Later, you can mirror your JS cluster logic by:

- Using octree nodes themselves as “clusters” and assigning subtrees to worker threads.
- Ensuring that integration writes are still per‑body and non‑overlapping.

But the above is enough to (a) push CPU cores, (b) prove that the ECS + ledger + domain stack can handle real work, and (c) keep determinism.
