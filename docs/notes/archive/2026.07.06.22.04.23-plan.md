# Plan: Honest two-channel star/planet formation (envelope gas-collapse + disc solids seed-and-grow) + HOPS315 doc + layered-FSM spec

## Context

The seed-and-grow condensation change (commit `c6e5e10`,
`docs/specs/seed-and-grow-condensation-realspec.md`) fixed the "smallest body is
669 M⊕" nonsense: a `:nebula` parcel condensing to the planetesimal tier now
spawns a ~1e16 kg rocky **seed** and debits the parent (which stays gas), instead
of promoting the whole parcel. **But the production dev sim now forms no stars**
because the change was applied indiscriminately to **gas-collapse** condensations
as well as to **solid-condensation** condensations. A star is a gas-collapse
outcome; treating it like a tiny planetesimal seed kills its ability to accrete
gas and grow. This gates the entire Phase-0 habitability handoff
(`docs/specs/phase0-habitability-handoff.md` §2 needs a `:star`).

**Root cause (verified in code).** `classify-next-state` uses a single mass-
based ladder that maps every sub-opacity condensation to `:planetesimal`. At
production resolution (`nebula-mass 4e30 / gas-count 1000 = pmass 4e27 kg`,
genesis.clj:276-281), every diffuse-gas parcel is below `opacity-limit-mass`
(5.97e27 kg, law/stellar.clj:32), so every condensation is classified as a
`:planetesimal`. The seed-and-grow seeder then replaces each parcel with a 1e16 kg
rock seed. A star needs ~40 parcels' worth of mass (`hydrogen-burning-mass
1.59e29 / 4e27`), so the only way to form a star is to let **gas-collapse**
condensations remain large enough to accrete. The fix is not to nominate a
single bootstrap core; it is to make the classifier distinguish the two physical
channels.

**Fix:** split the condensation pipeline by **environment**: envelope gas uses
core-collapse (whole-parcel or wide-accretion-radius sink), disc solids use
seed-and-grow. This is the architecture the HOPS315 correction note and the
temperature-composition note describe: cores form via Jeans instability in the
envelope; planetesimals form via solids particulating in the disc.

## Surfaced details from related notes and specs

Parallel subagents read the HOPS315 note, the correction note, the
temperature-composition-pressure note, the three explicit specs, the related
authoritative spec, and the current codebase. The details below must shape this
plan.

- **No single-core physical law.** The correction note
  (`docs/notes/2026.07.06.23.07-correction.md`) rejects a single hard-coded core.
  Cores/protostars form via **Jeans instability** at every unstable gas maximum;
  planetesimals form later when **solids particulate** in a cool disk. The
  single-bootstrap-core mechanism described in the previous draft of this plan
  has been discarded in favor of an honest two-channel classifier.
- **Two orthogonal channels.** The temperature-composition note
  (`docs/notes/2026.07.06.23.07.11-temperature-composition-pressure.md`) maps the
  natural gate to `disc-identification-system`:
  - **Envelope/collapsing gas** → Jeans instability → `:condensed-core`/gas-giant → stars.
  - **Disc** → silicate/refractory condensation → seed-and-grow planetesimals.
  `c/comp-condensed` already models the solid/gas partition; silicates are
  implicit in the solid fraction of rock-forming elements.
- **Roadmap context.** The specs place this fix in the larger
  `epic-phase0-physics-honesty.md` milestone sequence: M0 composition substrate,
  M1 metals, M2 condensation, **M3 core accretion + gradual mass transfer**, M4
  differentiation, M5 habitability handoff, M6 inspection. Core accretion and
  gradual mass transfer are not yet fully implemented in the code.
- **Authoritative formation spec.** `docs/specs/genesis-formation-authoritative.md`
  is the current end-to-end source of truth and supersedes older
  `phase0-jeans-driven-formation.md` and `phase0-protoplanetary-disk-implementation.md`.
- **Metal seeding is a prerequisite.** The code currently defaults to a
  Population-I metallicity (`Z ≈ 0.0167`), but several downstream consumers still
  behave as if metals are absent. M1/M2 must be considered working assumptions for
  M3 to be validated.

## Shape of the fix

```
                      condensing :nebula parcel
                                │
                ┌───────────────┴───────────────┐
                │  where is it? (disc-identification-system)  │
                │  envelope        vs           disc            │
                └───────────────┬───────────────┘
              envelope │                │ disc
                       ▼                ▼
    gas-collapse channel (Jeans + density    solids channel (c/comp-condensed,
    + isolation + not inside sink)             disc tag, seed-and-grow)
                       │                │
                       ▼                ▼
    classifier-system: promote whole     condensation-seeder-system:
    parcel to :condensed-core (or          spawn ~1e16 kg rocky seed,
    higher gas-giant state if mass          debit parent via
    already super-opacity)                  c/mass-flux-condense
                       │
                       ▼
    :condensed-core is a sink (mass_transfer sink-states)
      → wide c/accretion-radius (gas smoothing scale)
      → BHL-accretes gas, merges neighbours
      → climbs ladder: :condensed-core → :gas-giant → :brown-dwarf → :protostar → :star
```

The classifier and seeder still operate on the same frozen snapshot, but their
decision rule is now physical: **envelope vs disc**. No single designated core,
no special bootstrap helper. Any isolated Jeans-unstable envelope parcel can
become a `:condensed-core`. In practice the first one to appear will usually win
competitive accretion, but the mechanism is general and resolution-independent.

## Deliverable 1 — the code fix

### Step 0 — confirm the diagnosis empirically (before editing)

Headless tick loop on the **default** world; print the matter-state histogram.
Expect only `:nebula` + `:planetesimal`, never `:condensed-core`/`:star`. Re-run
after the fix to confirm a `:star` appears. Run once via a throwaway
`clojure -M:test` REPL or `-e` (avoid orphan JVMs).

```clojure
(require '[domain.genesis :as g] '[domain.ecs.core :as ecs] '[domain.ecs.components :as c])
(let [w0 (g/create-world)]
  (doseq [n [0 50 100 200 400]]
    (let [w (nth (iterate g/tick-world w0) n)]
      (println n (frequencies (map #(ecs/get-component w % c/matter-state)
                                   (ecs/entities-with w c/matter-state)))
               (:star? (g/system-summary w))))))
```

### Step 1 — `:condensed-core` in the classify ladder (`src/domain/stellar.clj`, `classify-next-state` ~948-1035)

Add a case mirroring the existing `:planetesimal`/`:gas-giant`/`:brown-dwarf`
cases (climbs by mass, **never** returns to `:nebula` — collapse is irreversible):

```clojure
:condensed-core (cond
                  (>= m law/hydrogen-burning-mass)  :protostar
                  (>= m law/deuterium-burning-mass) :brown-dwarf
                  (>= m law/opacity-limit-mass)     :gas-giant
                  :else                             :condensed-core)
```

Leave the `:nebula` branch untouched for now — it still returns `:planetesimal`
for a sub-opacity condensation. The environment split in Step 2 will route gas-
collapse condensations to `:condensed-core` before this mass ladder is reached.

### Step 2 — split the classifier by environment (`src/domain/stellar.clj`, `classifier-system`)

Replace the bootstrap helper with an **environment gate**. In the
`:classifier/transitions` `let` (where `gas-mass`, `eids`, `zones`, `transitions`,
`planetesimal-condenses`, `big-condenses`, `best-big-condense` are bound):

1. Determine each candidate's environment using `disc-identification-system`
   output or a helper derived from it. A parcel is **envelope** if it is not
   tagged as `:disc` and is still part of the collapsing cloud; it is **disc** if
   it has a `:disc` tag (or `:disc` matter-state / regime classification). For the
   first implementation, read the existing `c/disc-tag` or `c/regime` component set
   by `disc-identification-system` (stellar.clj:118-163).
2. For envelope condensations that pass the existing Jeans + density/accreted +
   isolation gate, emit `[eid :condensed-core]` and latch
   `c/accretion-radius = feeding-zone-factor × gas-smoothing-radius`. This is the
   honest gas-collapse path; it applies to **all** qualifying envelope parcels, not
   a single designated bootstrap.
3. For disc condensations, return `nil` (defer to `condensation-seeder-system`).
4. Keep the existing `best-big-condense` path for super-opacity condensations;
   they still promote directly to `:gas-giant` or higher.

**Remove `bootstrap-core-eid`.** The classifier no longer needs a single-designated-
core helper. It uses the same physical gate for every parcel.

### Step 3 — make the seeder disc-only (`src/domain/stellar.clj`, `condensation-seeder-system` ~1157-1224)

The seeder should only seed planetesimals from **disc** condensations. Update its
candidate selection:

- Filter candidates to those with a `:disc` environment tag.
- Remove the old bootstrap-core skip logic; it no longer exists.
- The one-shot marker and `condense-tick?` throttle remain unchanged.

This means in a pure-envelope test setup, the seeder emits nothing; in a disc
setup, it produces rocky seeds as before.

### Step 4 — make `:condensed-core` an accreting sink (`src/domain/mass_transfer.clj:27-28`)

Add `:condensed-core` to `sink-states`. **Without this the core cannot BHL-accrete
and never grows — this is the make-or-break line.** Leave the `#{:protostar :star}`
disk-former / fusion gates unchanged (mass_transfer.clj:200, stellar.clj:1254,
chemistry.clj:346, stellar.clj:460/2229): a `:condensed-core` is pre-protostar and
correctly forms no disk and does not fuse yet.

### Step 5 — structure participation & appearance (the enumerated-set ripple)

- **`resolved-shape`** (stellar.clj:2098-2126): add a `:condensed-core` case giving
  it a **gas-core density**, not rock. Recommended: use the existing
  `core-condensation-density` (stellar.clj:845, 1.0e-10 kg/m³) so the contracting
  core is a large diffuse first-core, consistent with the condensation trigger —
  `{:radius (sphere-radius m core-condensation-density) :density core-condensation-density}`.
  Optionally name it `condensed-core-density` for clarity.
- **Structure `resolved-eids` set** (stellar.clj:2176): add `:condensed-core` so
  Structure updates its radius/density as it accretes.
- **`temperature-system`** (stellar.clj:2229/2232): *leave `:condensed-core` out*
  (it stays cold; it should not virial-heat until it is a `:protostar`). Note the
  choice in a comment.
- **`law/field.clj:87` `hydro-em-active?`** (`#{:nebula :protostar}`): optional —
  defer. The core becomes `:protostar` before SPH/EM participation matters.
- **Rendering (cosmetic — verified no-crash):** the render shape `case`
  (render.clj:1473) has a fall-through default (the substellar/planet branch, line
  1573), so a `:condensed-core` renders as a plain body without crashing. For a
  proper look add a `:condensed-core` case in `body-appearance` (render.clj:885-909,
  compact warm contracting cloud) and `infra/inspect.clj` `state-label` (247) +
  `state-color` (256). Both already have safe defaults.
- **No Malli/registry change:** `matter-state-schema` (law/stellar.clj:204) types
  `:state` as `keyword?` — a new *value* needs no enum edit. Update the inline
  state-list comments (`ecs/components.clj` state list, law/stellar.clj:214).

### Step 6 — tests (`test/domain/`)

**Re-scope existing seeder unit tests** (`condensation_seeder_test.clj`): they
spawn a lone sub-opacity parcel with **no disc tag**, so under the new rules they
hit the envelope/core-collapse path and the seeder emits nothing. Fix: give the
test parcels a `:disc` tag (or place them in a world where `disc-identification-
system` has tagged the region as disc) so the seeder sees them as planetesimal-
forming condensations. Remove the old dummy-sink geometry workaround.

**New tests:**
- **`sub-opacity-cloud-forms-a-star`** (the regression guard — put in
  `dominant_star_test.clj` or a new `star_formation_test.clj`; reuse the
  `collapsing-clump` harness): `pmass 4e27` and ~64-128 parcels (enough to reach
  `hydrogen-burning-mass`); tick through `genesis/tick-world`; assert one or more
  `:star`s emerge and ≥1 entity has `c/accretion-radius`. **This is the test whose
  absence let the regression ship.**
- **`classifier-uses-envelope-for-cores`**: in an envelope-like world, an isolated
  Jeans-unstable `:nebula` parcel → `:condensed-core` with a wide feeding-zone
  radius.
- **`classifier-uses-disc-for-planetesimals`**: in a disc-like world, a condensing
  `:nebula` parcel stays `:nebula` in the classifier and the seeder emits a seed.
- **`seeder-handles-only-disc`**: without a `:disc` tag, the seeder emits no seeds
  even when a parcel condenses.
- **`condensed-core-climbs-the-ladder`** (unit on `classify-next-state`):
  `:condensed-core` stays put below opacity, → `:gas-giant`/`:brown-dwarf`/
  `:protostar` as mass crosses each threshold, and **never** → `:nebula`/`:planetesimal`.
- **`multiple-envelope-cores-allowed`** (optional): with two widely separated
  envelope parcels, both can become `:condensed-core` in the same tick if no sink
  exclusion zone overlaps.
- **Keep green:** `classifier-still-promotes-big-condensations`,
  `seeding-is-bounded-in-collapse` (gas-count 100 → super-opacity, unaffected),
  `dominant_star_test`, `formation_integration_test`, `genesis_test`,
  `architecture_test`, and the `persistent-cache-*` determinism tests.

## Deliverable 2 — HOPS315 research/gaps doc

New `docs/research/physics/hops315-condensation-and-planet-formation.md` (matches
the existing `docs/research/physics/` convention, e.g. `stellar-nebula-mass-hierarchy.md`).
Drawn from `docs/notes/Tell me what we've learned studying HOPS315 with j.md`:

- **HOPS-315 summary:** SiO gas cooling ~1300→200 °C, crystalline forsterite/CAI
  analogues condensing within ~1-2.2 AU — the observed "time zero" of rocky
  planet building. The protostar forms from the *envelope/gas*; solids condense in
  the *inner disk* — **two distinct condensation regimes**.
- **Gaps vs current Truth:** (1) no dust/grain continuum phase; (2) the
  parcel-collapse vs disk-solids distinction was implicit and mis-gated (this bug);
  (3) collision growth lacks stirring/fragmentation.
- **Grounding** seed-and-grow + this fix in the literature (super-particles;
  dust→pebble→planetesimal via streaming instability; Garaud-style dust→planetesimal
  conversion) — cite the note. State epistemic invariants Truth commits to
  (mass/momentum conservation; dust→planetesimals→planets direction) vs stylistic
  choices.
- **Cross-link the fix:** "star formation = gas-collapse core (`:condensed-core →
  :star`); planetesimals = disk-solids seed-and-grow — different conditions,
  different channels." Emphasize that the classifier now uses this split directly
  rather than relying on a single designated core.

## Deliverable 3 — layered-FSM design spec

New `docs/specs/state-machine-nebula-to-life.md` (design doc, **not** code).
Transcribe the note's culminating architecture into Truth-style canonical catalogs.
Call out `:condensed-core` (Deliverable 1) as the first shipped increment and
state clearly that the Matter machine treats **envelope gas-collapse** and
**disc solid-condensation** as separate channels from the start. In the long-term
FSM, `disc-identification-system` is the gate between the two channels.

- **Principle:** a *stack of coupled FSMs*, each owning one question, one active
  state, one owner system, ordered guards, allowed successors. "The FSM is the
  interpreter of simulation observables, not the simulation." Rich internal state →
  compressed Phase-0 handoff summary.
- **Five machines** (catalog tables: state · owner · observables · entry guard ·
  exit guard · successors · notes): **Matter** (`domain.stellar`/`domain.planet-formation`:
  nebula, collapsing-gas, **condensed-core**, protostar, star, stellar-remnant,
  dust/pebble, planetesimal, asteroid, comet, protoplanet, dwarf/planet,
  gas/ice-giant, brown-dwarf, debris, ring-particle), **Role** (`domain.orbital`),
  **Environment** (`domain.environment`, ordered guards), **Atmosphere/EM**
  (`domain.atmosphere`/`domain.em`), **Biosphere** (`domain.biology`/`domain.ecology`,
  runs only when upstream marks the world eligible).
- **Modifier catalog** (bias transitions, not states): has-large-moon,
  giant-planet-shielding/scattering, heavy-bombardment, tidal-heating, stellar-youth-XUV,
  feedstock, dynamo-decline, refugia — solves the Mars/Pluto/Moon/Jupiter "one label
  can't carry it all" problem.
- **Phase-0 handoff projection:** rich internal state → coarse `:planet-candidate`
  record per `phase0-habitability-handoff.md`.
- **Component/ownership/classifier mapping** + a **phased implementation order**
  (matter+role coarse → atmosphere/EM → handoff projection → biosphere). Note
  `disc-identification-system` (stellar.clj:118-163) as the natural future
  discriminator between the gas-collapse and disk-solids condensation channels.
- Mark clearly: **design layer**, aspirational beyond the shipped `:condensed-core`;
  it does not describe current behavior.

## Notes / decisions

- **One genuine design choice:** the `:condensed-core` density in `resolved-shape`
  (Step 5). Recommended: reuse `core-condensation-density` (1e-10 kg/m³). Everything
  else is mechanical. This means a large density jump at the `:condensed-core → :gas-giant`
  transition (1e-10 → 1e3 kg/m³) — acceptable in the toy (real first cores do collapse
  dramatically), and temperature only engages at `:protostar` so no spurious virial spike.
- **Envelope promotion is ungated by `condense-tick?`** in the classifier — this mirrors the
  existing `best-big-condense` whole-parcel promotion. It is a direct collapse event, not a seeding
  event, so the per-tick seeding throttle does not apply.
- **Disc seeding remains gated by `condense-tick?`** — the seeder still uses its existing throttle to
  bound the number of rocky seeds.
- **No single designated core.** Any isolated Jeans-unstable envelope parcel can become a
  `:condensed-core`. The first one to collapse usually wins competitive accretion, but the mechanism
  is general and not hard-coded to one eid.
- **Option A (`:condensed-core`) remains the right state.** The difference from the previous plan is that
  the state now applies to the honest gas-collapse channel, not to a one-off bootstrap. Reusing
  `:planetesimal` for a collapsing gas core would label it as a rocky body — the same dishonesty
  seed-and-grow set out to kill.
