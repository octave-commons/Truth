# execute my intent, expand my meaning, create the μ specs

Here’s a first μ‑spec pass: small, focused, executable specs that encode the ontology you described and force the architecture into existence. Where I say “implementation TBD”, that’s deliberate: these tests should fail until you fill in the corresponding `shape.*`, `law.*`, `domain.*` namespaces.

## μ0 – Shapes, Claims, Contracts

Goal: make the *category* vs *contract* split executable.

```clojure
(ns shape.core-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.core :as shape]
    [law.contract :as contract]))

;; μ0.0: Shapes are purely descriptive, not evaluative.
(deftest shape-is-pure-description
  (testing "Shape describes form and meaning, not validity"
    (let [s (shape/->shape
              {:id          (shape/new-shape-id)
               :kind        :state
               :form        {:x int? :y int?}
               :name        "position"
               :description "2D integer position in world space"})]
      (is (= :state (:kind s)))
      (is (= "position" (:name s)))
      (is (map? (:form s)))
      ;; No validity is implied just by constructing a Shape.
      (is (nil? (:valid? s))))))

;; μ0.1: Claims assert that a concrete value instantiates a Shape.
(deftest claim-binds-shape-to-value
  (testing "Claim pairs a Shape with a concrete value and context"
    (let [shape-id (shape/new-shape-id)
          claim    (shape/->claim
                     {:id          (shape/new-claim-id)
                      :shape-id    shape-id
                      :value       {:x 10 :y 20}
                      :context     {:tick 42
                                    :entity-id 1001}
                      :asserted-by :system/physics})]
      (is (= shape-id (:shape-id claim)))
      (is (= {:x 10 :y 20} (:value claim)))
      (is (= 42 (get-in claim [:context :tick])))
      (is (= :system/physics (:asserted-by claim))))))

;; μ0.2: Contracts govern Shapes and return explicit results.
(deftest contract-validates-claim
  (testing "Contract validates values for its governed Shape"
    (let [shape      (shape/->shape
                       {:id          (shape/new-shape-id)
                        :kind        :state
                        :form        {:x int? :y int?}
                        :name        "position"
                        :description "2D integer position"})
          c          (contract/->contract
                       {:id         (shape/new-resource-id)
                        :shape-id   (:id shape)
                        :kind       :type
                        :schema     {:x int? :y int?}
                        :name       "position-type"
                        :description "position must have integral x and y"})
          good-claim (shape/->claim
                       {:id          (shape/new-claim-id)
                        :shape-id    (:id shape)
                        :value       {:x 0 :y -5}
                        :context     {:tick 1}
                        :asserted-by :system/physics})
          bad-claim  (shape/->claim
                       {:id          (shape/new-claim-id)
                        :shape-id    (:id shape)
                        :value       {:x 0.5 :y -5}
                        :context     {:tick 1}
                        :asserted-by :system/physics})]
      (is (= ::contract/ok
             (contract/validate c good-claim)))
      (let [res (contract/validate c bad-claim)]
        (is (= ::contract/violation (:result res)))
        (is (= (:id bad-claim)
               (get-in res [:claim :id])))))))

;; μ0.3: Type vs Quality contracts differ in “extra data” handling.
(deftest type-vs-quality-contracts
  (testing "Type contracts forbid extra keys, quality contracts allow them"
    (let [shape-id  (shape/new-shape-id)
          type-c    (contract/->contract
                      {:id       (shape/new-resource-id)
                       :shape-id shape-id
                       :kind     :type
                       :schema   {:mass number?}
                       :name     "mass-type"})
          quality-c (contract/->contract
                      {:id       (shape/new-resource-id)
                       :shape-id shape-id
                       :kind     :quality
                       :schema   {:mass (fn [m] (and (number? m) (pos? m)))}
                       :name     "positive-mass"})
          bare      (shape/->claim
                      {:id          (shape/new-claim-id)
                       :shape-id    shape-id
                       :value       {:mass 10.0}
                       :context     {:tick 1}
                       :asserted-by :system/physics})
          extended  (shape/->claim
                      {:id          (shape/new-claim-id)
                       :shape-id    shape-id
                       :value       {:mass 10.0 :debug "extra"}
                       :context     {:tick 1}
                       :asserted-by :system/physics})]
      (is (= ::contract/ok (contract/validate type-c bare)))
      (is (= ::contract/ok (contract/validate quality-c bare)))
      ;; Type must reject extra keys.
      (is (= ::contract/violation (:result (contract/validate type-c extended))))
      ;; Quality may accept extra keys if explicit constraints hold.
      (is (= ::contract/ok (contract/validate quality-c extended))))))

```

These μ‑specs force:

- `shape.core` to provide `->shape`, `->claim`, and id constructors.
- `law.contract` to decide `:kind` semantics (`:type` vs `:quality`), and return either `::ok` or a structured violation.

## μ1 – Registry invariants

Goal: make “Registry as lawful index over resources” concrete.

```clojure
(ns law.registry-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.core :as shape]
    [law.contract :as contract]
    [law.registry :as registry]))

;; μ1.0: Registry enforces a single resource contract.
(deftest registry-enforces-contract
  (testing "Only resources that pass the registry's contract can be added"
    (let [shape      (shape/->shape
                       {:id          (shape/new-shape-id)
                        :kind        :state
                        :form        {:id int?}
                        :name        "simple-resource"
                        :description "demo"})
          res        {:id 1}
          bad-res    {:id "not-int"}
          res-schema {:id int?}
          res-ct     (contract/->contract
                       {:id       (shape/new-resource-id)
                        :shape-id (:id shape)
                        :kind     :type
                        :schema   res-schema
                        :name     "simple-resource-type"})
          reg0       (registry/->registry res-ct)
          reg1       (registry/add reg0 res)]
      (is (= res-ct (:resource-contract reg1)))
      (is (= res (registry/get-by-id reg1 1)))
      (is (thrown-with-msg?
            clojure.lang.ExceptionInfo
            #"contract.*violation"
            (registry/add reg1 bad-res))))))

;; μ1.1: Registry maintains id → index and is self-consistent.
(deftest registry-index-consistency
  (testing "Index mirrors the items vector and can be recomputed"
    (let [shape   (shape/->shape
                    {:id          (shape/new-shape-id)
                     :kind        :state
                     :form        {:id int?}
                     :name        "simple-resource"
                     :description "demo"})
          ct      (contract/->contract
                    {:id       (shape/new-resource-id)
                     :shape-id (:id shape)
                     :kind     :type
                     :schema   {:id int?}
                     :name     "simple-resource-type"})
          reg     (-> (registry/->registry ct)
                      (registry/add {:id 1})
                      (registry/add {:id 2})
                      (registry/add {:id 3}))
          rebuilt (registry/rebuild-index reg)]
      (is (= (:index reg) (:index rebuilt)))
      (is (= 3 (count (:items reg))))
      (is (= {:id 2} (registry/get-by-id reg 2))))))

;; μ1.2: Resource ids in the registry must be unique.
(deftest registry-rejects-duplicate-ids
  (testing "Adding a resource with an existing id fails fast"
    (let [shape (shape/->shape
                  {:id          (shape/new-shape-id)
                   :kind        :state
                   :form        {:id int?}
                   :name        "simple-resource"
                   :description "demo"})
          ct    (contract/->contract
                  {:id       (shape/new-resource-id)
                   :shape-id (:id shape)
                   :kind     :type
                   :schema   {:id int?}
                   :name     "simple-resource-type"})
          reg   (-> (registry/->registry ct)
                    (registry/add {:id 1}))]
      (is (thrown-with-msg?
            clojure.lang.ExceptionInfo
            #"duplicate.*id"
            (registry/add reg {:id 1}))))))

```

These specs force `law.registry` to:

- Keep `items` and `index` in sync.
- Enforce uniqueness and contract validation at the boundary.

## μ2 – Ledger determinism and Merkle semantics

Goal: encode “all state derivable from ledger” and deterministic replay.

```clojure
(ns law.ledger-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.core :as shape]
    [law.contract :as contract]
    [law.registry :as registry]
    [law.ledger :as ledger]))

(defn demo-position-shape+contract []
  (let [shape (shape/->shape
                {:id          (shape/new-shape-id)
                 :kind        :state
                 :form        {:x int? :y int?}
                 :name        "position"
                 :description "2D integer position"})
        ct    (contract/->contract
                {:id       (shape/new-resource-id)
                 :shape-id (:id shape)
                 :kind     :type
                 :schema   {:x int? :y int?}
                 :name     "position-type"})]
    {:shape shape :contract ct}))

;; μ2.0: Applying the same sequence of events yields the same state.
(deftest replay-is-deterministic
  (testing "Given the same initial state and events, replaying yields the same snapshot"
    (let [{:keys [shape contract]} (demo-position-shape+contract)
          entity-id 1001
          base-ledger (ledger/empty-ledger)
          ;; build two identical sequences of events
          e1 (ledger/->event
               {:timestamp 1
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id shape)
                              :value       {:x 0 :y 0}
                              :context     {:tick 1
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          e2 (ledger/->event
               {:timestamp 2
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id shape)
                              :value       {:x 1 :y 0}
                              :context     {:tick 2
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          l1 (-> base-ledger (ledger/append e1) (ledger/append e2))
          l2 (-> base-ledger (ledger/append e1) (ledger/append e2))
          snapshot1 (ledger/materialize-snapshot l1 {:tick 2})
          snapshot2 (ledger/materialize-snapshot l2 {:tick 2})]
      (is (= snapshot1 snapshot2))
      ;; Optional: snapshot hash derived from Merkle root.
      (is (= (ledger/snapshot-hash snapshot1)
             (ledger/snapshot-hash snapshot2))))))

;; μ2.1: Changing any event changes the Merkle root.
(deftest merkle-root-is-sensitive-to-event-changes
  (testing "Modifying an event changes the Merkle root and snapshot hash"
    (let [{:keys [shape]} (demo-position-shape+contract)
          entity-id 1001
          base-ledger (ledger/empty-ledger)
          e1 (ledger/->event
               {:timestamp 1
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id shape)
                              :value       {:x 0 :y 0}
                              :context     {:tick 1
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          e2 (ledger/->event
               {:timestamp 2
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id shape)
                              :value       {:x 1 :y 0}
                              :context     {:tick 2
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          e2' (update e2 :claims
                      (fn [[c]] [(update c :value assoc :x 2)]))
          l1  (-> base-ledger (ledger/append e1) (ledger/append e2))
          l2  (-> base-ledger (ledger/append e1) (ledger/append e2'))
          root1 (ledger/merkle-root l1)
          root2 (ledger/merkle-root l2)
          s1    (ledger/materialize-snapshot l1 {:tick 2})
          s2    (ledger/materialize-snapshot l2 {:tick 2})]
      (is (not= root1 root2))
      (is (not= (ledger/snapshot-hash s1)
                (ledger/snapshot-hash s2))))))

```

These μ‑specs force `law.ledger` to:

- Represent a ledger.
- Append Events.
- Materialize a Snapshot deterministically.
- Compute a Merkle root and snapshot hash that are sensitive to event payloads.

## μ3 – Systems, Stores, and deterministic ticks

Goal: encode your ECS tick semantics, history ring buffer, and event queues.

```clojure
(ns domain.system-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [shape.core :as shape]
    [law.contract :as contract]
    [law.registry :as registry]
    [law.ledger :as ledger]
    [domain.system :as system]))

(defn demo-system []
  ;; A toy system that owns a position component store
  ;; and increments x by 1 each tick.
  (let [pos-shape   (shape/->shape
                      {:id          (shape/new-shape-id)
                       :kind        :state
                       :form        {:x int? :y int?}
                       :name        "position"
                       :description "2D integer position"})
        pos-ct      (contract/->contract
                      {:id       (shape/new-resource-id)
                       :shape-id (:id pos-shape)
                       :kind     :type
                       :schema   {:x int? :y int?}
                       :name     "position-type"})
        component-store (system/->component-store
                          {:resource-type :component/position
                           :window        2
                           :gap           1})
        tick-ct      (contract/->contract
                       {:id       (shape/new-resource-id)
                        :shape-id nil
                        :kind     :type
                        :schema   {:tick int?}
                        :name     "tick-contract"})
        sys          (system/->system
                       {:id                  :system/physics
                        :component-store     component-store
                        :component-contract  pos-ct
                        :tick-contract       tick-ct
                        :watched-event-kinds [:component-updated]
                        :event-queue         []})]
    {:system sys
     :pos-shape pos-shape
     :pos-contract pos-ct}))

;; μ3.0: tick consumes queued events, advances the store, and is deterministic.
(deftest tick-advances-store-deterministically
  (testing "Tick processes queued events and advances history deterministically"
    (let [{:keys [system pos-shape]} (demo-system)
          entity-id 1001
          e0 (ledger/->event
               {:timestamp 1
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id pos-shape)
                              :value       {:x 0 :y 0}
                              :context     {:tick 1
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          ;; two identical worlds: same initial ledger and system state
          base-ledger (ledger/empty-ledger)
          l1 (ledger/append base-ledger e0)
          l2 (ledger/append base-ledger e0)
          sys1 (system/queue-event system e0)
          sys2 (system/queue-event system e0)
          ;; single tick should consume event and increment x to 1 in both worlds
          {sys1' :system led1 :ledger} (system/tick sys1 l1)
          {sys2' :system led2 :ledger} (system/tick sys2 l2)
          c1 (system/observe sys1' entity-id 0)
          c2 (system/observe sys2' entity-id 0)]
      ;; queues are empty after tick
      (is (empty? (:event-queue sys1')))
      (is (empty? (:event-queue sys2')))
      ;; same ledger and same observed component state
      (is (= led1 led2))
      (is (= (:value c1) (:value c2)))
      ;; system-specific law: physics increments x by 1 per tick
      (is (= {:x 1 :y 0} (:value c1))))))

;; μ3.1: snapshot retention window behaves like a ring buffer.
(deftest snapshot-retention-window
  (testing "Component store retains only the configured number of snapshots"
    (let [{:keys [system pos-shape]} (demo-system)
          entity-id 1001
          base-ledger (ledger/empty-ledger)
          ;; seed initial component
          e0 (ledger/->event
               {:timestamp 1
                :kind      :component-updated
                :cause     :test
                :claims    [(shape/->claim
                             {:id          (shape/new-claim-id)
                              :shape-id    (:id pos-shape)
                              :value       {:x 0 :y 0}
                              :context     {:tick 1
                                            :entity-id entity-id}
                              :asserted-by :system/physics})]})
          ;; run three ticks, window=2 => only last two snapshots retained
          {sys1 :system led1 :ledger} (-> {:system (system/queue-event system e0)
                                           :ledger (ledger/append base-ledger e0)}
                                          (system/tick))
          {sys2 :system led2 :ledger} (system/tick {:system sys1 :ledger led1})
          {sys3 :system led3 :ledger} (system/tick {:system sys2 :ledger led2})
          store (:component-store sys3)]
      (is (= 2 (system/store-window store)))
      (is (<= (count (system/store-history store)) 2))
      ;; oldest snapshot should have been evicted
      (is (nil? (system/observe sys3 entity-id 2)))
      ;; but recent snapshots are available
      (is (map? (system/observe sys3 entity-id 0)))
      (is (map? (system/observe sys3 entity-id 1))))))

```

These specs force `domain.system` to:

- Define a `System` category (data) plus `tick`, `queue-event`, `observe`, and `component-store` behavior.
- Enforce the ring‑buffer semantics you want for component history.

## 8. How to iterate

If you wire these four test namespaces into your test runner, you get an immediate Red wall:

- `shape.core`, `law.contract`, `law.registry`, `law.ledger`, `domain.system` don’t exist yet.
- Once you scaffold them with minimal records and functions, you’ll get more precise failures (wrong shapes, missing invariants, etc.).

From there, Red‑Green‑Refactor becomes:

1. Make `shape.core` compile and satisfy μ0.
2. Make `law.contract` and `law.registry` satisfy μ0–μ1.
3. Make `law.ledger` satisfy μ2 with a minimal Merkle implementation.
4. Make `domain.system` satisfy μ3 with the simplest plausible ECS store.

If you want the next step to be the minimal `shape.core` + `law.contract` implementation needed to turn μ0 green, I can draft those namespaces next.
