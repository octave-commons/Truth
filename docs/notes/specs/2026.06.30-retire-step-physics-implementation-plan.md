# Implementation Plan: Retire `step-physics` + Centralize Spatial Index

**Spec:** `2026.06.29-unified-physical-state-integrator-spec.md` §7
**Created:** 2026-06-30
**Status:** COMPLETE

---

## Context

The `step-physics` function (`phase0.clj:594-619`) still runs 7 systems serially
after the fold. The spec says "nothing runs serially after the fold." This plan
completes §7 by converting all serial barrier systems to fan-out emitters and
centralizing the spatial index.

The integrator uses the **per-field-updater approach** (§8 Q2) — no unified
`:component/physical`. Derived quantities (radius, density, pressure, oblateness,
rotation-axis) stay as separate single-owner systems. The integrator owns only the
contended accumulated fields: position, velocity, mass, angular-momentum,
temperature, composition.


## Part B: Convert collision handler to emit influences

The merge handler (`stellar.clj:1763-1881`) writes 12 physical components directly
on the survivor — single-writer violation. The integrator already handles
`c/absorb-merge` packets (`integrator.clj:97-135`).

### B1. Convert merge case to emit `c/absorb-merge` + `c/consumed-merge`
- **File:** `src/domain/stellar.clj` (lines 1796-1880)
- Instead of `ecs/put-component big c/position pos'` etc., emit:
  ```clojure
  (ecs/put-component big c/absorb-merge
    [{:mass ms, :velocity vs, :position r-small
      :angular-momentum L-total, :composition (:composition ms*)
      :temperature (:temperature ms*), :radius rs}])
  ```
- Instead of `ecs/despawn small`, emit:
  ```clojure
  (ecs/put-component small c/consumed-merge true)
  ```
- Derived quantities (radius, density, pressure, oblateness, rotation-axis) are
  re-derived by their respective systems next tick — one-tick Jacobi delay.

### B2. Convert shatter case to emit `c/spawn-request-shatter` + `c/consumed-merge`
- **File:** `src/domain/stellar.clj` (lines 1740-1761)
- Instead of calling `spawn-clump` inline, emit:
  ```clojure
  (ecs/put-component big c/spawn-request-shatter
    [(spec 1.0) (spec -1.0)])
  (ecs/put-component small c/consumed-merge true)
  ```
- `materialize-lifecycle` already handles `c/spawn-request-shatter` (`phase0.clj:561`)

### B3. Move collision detection into parallel fan-out
- Move `collision-detection-system` into `physics-systems-parallel`
- Remove `:stage :barrier` from registry entry
- Update `:writes` to include `c/absorb-merge`, `c/consumed-merge`

## Key design decisions (resolved)

1. **Per-field-updater approach** (§8 Q2) — integrator owns contended fields, derived
   quantities stay as separate systems. No unified `:component/physical`.
2. **Octree centralization** — one system builds, all consumers read. Eliminates
   redundant O(n log n) construction.
3. **Collision handler conversion** — emit `c/absorb-merge` + `c/consumed-merge`
   instead of writing physical state. Integrator applies merge next tick.
4. **Shatter case** — emit `c/spawn-request-shatter` + `c/consumed-merge`. Already
   supported by `materialize-lifecycle`.
5. **Derived quantities** — radius, density, pressure, oblateness, rotation-axis
   re-derived by their respective systems next tick (one-tick Jacobi delay).
