# Aight, but where are my ECS primatives? you missed the point, hard coding all this now

Fair correction. Everything above bypassed the ECS layer and hardcoded body-specific logic directly into the orbital system — that's the wrong substrate. Let me back up and build the actual primitives first, then everything else composes on top of them.

***

## The ECS contract

Three things, nothing else:

- **Entity** — an opaque id. No data. Just an identity.
- **Component** — a typed datum associated with an entity. The type is the key.
- **System** — a pure function `(world → world)` that queries components and returns updated components.

World state is a single map. No inheritance, no OOP, no implicit coupling between systems. Everything is a data query over that map.

***

## `domain.ecs.core`

```clojure
(ns domain.ecs.core
  "ECS primitives for Gates of Truth.
   - Entity: opaque UUID
   - Component store: {component-type {entity-id value}}
   - World: {:entities #{id} :components {type {eid value}} :tick long}
   - System: (fn [world] world')
   All functions are pure. No I/O. No side effects.")

;; ---------------------------------------------------------------------------
;; Entity
;; ---------------------------------------------------------------------------

(defn new-entity
  "Allocate a new entity id. An entity is just a UUID — no data attached."
  []
  (java.util.UUID/randomUUID))

;; ---------------------------------------------------------------------------
;; World constructor
;; ---------------------------------------------------------------------------

(defn empty-world
  "An empty ECS world."
  []
  {:entities   #{}
   :components {}   ;; {component-type {entity-id value}}
   :tick       0})

;; ---------------------------------------------------------------------------
;; Entity lifecycle
;; ---------------------------------------------------------------------------

(defn spawn
  "Add an entity to the world. Returns updated world.
   Does not attach any components — use put-component for that."
  [world]
  (let [eid (new-entity)]
    [(update world :entities conj eid) eid]))

(defn despawn
  "Remove entity and all its components from the world."
  [world eid]
  (-> world
      (update :entities disj eid)
      (update :components
              (fn [comps]
                (reduce-kv (fn [m ctype store]
                             (assoc m ctype (dissoc store eid)))
                           {}
                           comps)))))

;; ---------------------------------------------------------------------------
;; Component read / write
;; ---------------------------------------------------------------------------

(defn put-component
  "Associate component-type ctype with value v for entity eid.
   Creates the component store for ctype if it doesn't exist."
  [world eid ctype v]
  (assoc-in world [:components ctype eid] v))

(defn get-component
  "Get the value of component ctype for entity eid. Returns nil if absent."
  [world eid ctype]
  (get-in world [:components ctype eid]))

(defn remove-component
  "Dissociate component ctype from entity eid."
  [world eid ctype]
  (update-in world [:components ctype] dissoc eid))

(defn has-component?
  "True if entity eid has component ctype."
  [world eid ctype]
  (contains? (get-in world [:components ctype] {}) eid))

;; ---------------------------------------------------------------------------
;; Queries — the heart of ECS
;; ---------------------------------------------------------------------------

(defn entities-with
  "Return the set of entity ids that have ALL of the given component types.
   This is the primary query primitive — systems use this to find their targets."
  [world & ctypes]
  (when (seq ctypes)
    (let [[first-type & rest-types] ctypes
          base (set (keys (get-in world [:components first-type] {})))]
      (reduce (fn [eids ctype]
                (let [store (get-in world [:components ctype] {})]
                  (into #{} (filter #(contains? store %)) eids)))
              base
              rest-types))))

(defn components-of
  "Return a map of {ctype value} for all components on entity eid."
  [world eid]
  (reduce-kv (fn [m ctype store]
               (if-let [v (get store eid)]
                 (assoc m ctype v)
                 m))
             {}
             (:components world)))

(defn all-of
  "Return a seq of [eid {ctype value ...}] for all entities that have
   ALL of the given ctypes. The map contains only the requested ctypes."
  [world & ctypes]
  (when-let [eids (apply entities-with world ctypes)]
    (map (fn [eid]
           [eid (into {} (map (fn [ct] [ct (get-component world eid ct)])) ctypes)])
         eids)))

;; ---------------------------------------------------------------------------
;; Batch update — the write side of a system
;; ---------------------------------------------------------------------------

(defn update-component
  "Apply f to the current value of ctype on eid. f receives current value
   (or nil if absent). Useful inside system reduce loops."
  [world eid ctype f]
  (update-in world [:components ctype eid] f))

(defn put-components
  "Associate multiple components at once from a map {ctype value}.
   Convenience for spawn + initial components."
  [world eid component-map]
  (reduce-kv (fn [w ct v] (put-component w eid ct v))
             world
             component-map))

;; ---------------------------------------------------------------------------
;; System runner
;; ---------------------------------------------------------------------------

(defn run-system
  "Run a single system (fn [world] world') over the world.
   Systems are pure — they receive world, return world."
  [world system-fn]
  (system-fn world))

(defn run-systems
  "Run a seq of systems in order over the world.
   Returns final world state."
  [world system-fns]
  (reduce run-system world system-fns))

(defn tick
  "Advance the world by one tick: run all systems, increment :tick."
  [world system-fns]
  (-> (run-systems world system-fns)
      (update :tick inc)))
```

## Component types as keywords — the vocabulary

(ns domain.ecs.components

## Now rewrite `domain.orbital.system` on top of ECS

This replaces the hardcoded body-vec approach entirely:

```clojure
(ns domain.orbital.system
  "Orbital physics system for Gates of Truth.
   Queries position + velocity + mass components via ECS.
   Returns world with updated position + velocity components."
  (:require
    [domain.ecs.core        :as ecs]
    [domain.ecs.components  :as c]
    [domain.gravity.barnes-hut :as bh]
    [domain.orbital.integrator :as integrator]
    [shape.spatial          :as sp]))

(defn- world->bodies
  "Project ECS world into a seq of body maps for the Barnes-Hut tree."
  [world]
  (map (fn [[eid comps]]
         {:id       eid
          :mass     (comps c/mass)
          :radius   (comps c/radius)
          :kind     (comps c/body-kind)
          :position (comps c/position)
          :velocity (comps c/velocity)})
       (ecs/all-of world c/position c/velocity c/mass c/radius c/body-kind)))

(defn- apply-body-back
  "Write updated position and velocity for eid back into world."
  [world eid body]
  (-> world
      (ecs/put-component eid c/position (:position body))
      (ecs/put-component eid c/velocity (:velocity body))))

(defn orbital-system
  "ECS system: advances all entities with position+velocity+mass
   by one Leapfrog step under mutual gravitational attraction."
  [G theta dt]
  (fn [world]
    (let [bodies (world->bodies world)
          tree   (bh/build-tree bodies)]
      (reduce (fn [w body]
                (let [updated (integrator/leapfrog-step
                                body
                                (fn [b] (bh/acceleration G theta tree b))
                                dt)]
                  (apply-body-back w (:id body) updated)))
              world
              bodies))))
```

## μ-specs for ECS primitives

```clojure
(ns domain.ecs.core-test
  (:require
    [clojure.test :refer [deftest is testing]]
    [domain.ecs.core       :as ecs]
    [domain.ecs.components :as c]))

;; μ-ecs-1: spawn returns world with new entity in :entities
(deftest spawn-adds-entity
  (let [[w eid] (ecs/spawn (ecs/empty-world))]
    (is (contains? (:entities w) eid))))

;; μ-ecs-2: put-component + get-component round-trips
(deftest component-round-trip
  (let [[w eid] (ecs/spawn (ecs/empty-world))
        w'      (ecs/put-component w eid c/mass 42.0)]
    (is (= 42.0 (ecs/get-component w' eid c/mass)))))

;; μ-ecs-3: entities-with returns only entities having ALL ctypes
(deftest entities-with-all
  (let [[w e1] (ecs/spawn (ecs/empty-world))
        [w e2] (ecs/spawn w)
        w      (ecs/put-components w e1 {c/position [0 0 0] c/mass 1.0})
        w      (ecs/put-components w e2 {c/position [1 1 1]})]
    ;; e1 has both position and mass, e2 only position
    (is (= #{e1} (ecs/entities-with w c/position c/mass)))
    (is (= #{e1 e2} (ecs/entities-with w c/position)))))

;; μ-ecs-4: despawn removes entity and all its components
(deftest despawn-removes-all
  (let [[w eid] (ecs/spawn (ecs/empty-world))
        w       (ecs/put-component w eid c/mass 1.0)
        w       (ecs/despawn w eid)]
    (is (not (contains? (:entities w) eid)))
    (is (nil? (ecs/get-component w eid c/mass)))))

;; μ-ecs-5: tick increments :tick counter
(deftest tick-increments
  (let [w  (ecs/empty-world)
        w' (ecs/tick w [])]
    (is (= 1 (:tick w')))))

;; μ-ecs-6: systems compose and run in order
(deftest systems-compose-in-order
  (let [[w eid] (ecs/spawn (ecs/empty-world))
        w       (ecs/put-component w eid :test/counter 0)
        inc-sys (fn [world]
                  (ecs/update-component world eid :test/counter
                                        (fnil inc 0)))
        w'      (ecs/tick w [inc-sys inc-sys inc-sys])]
    (is (= 3 (ecs/get-component w' eid :test/counter)))))
```

## What this gives you

Everything downstream now composes cleanly. A planet is not a hardcoded `Body` record — it's an entity with `position`, `velocity`, `mass`, `radius`, `body-kind` components. The atmosphere system queries `atmos-cell` + `cell-id`. The biome system queries `biome-cell`. The render system queries `renderable` + `position`. Each system is an independent `(fn [world] world')` — they're hot-swappable, testable in isolation, and can be toggled per LOD zone by simply including or excluding them from the `run-systems` seq.
