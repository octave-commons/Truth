# ECS Spec: Double-Buffered, Single-Writer, Thread-Per-System

**Status:** IMPLEMENTED. The single-writer invariant holds and is enforced
(`domain.ecs.registry/assert-single-writer!`, `test/architecture_test.clj`). The
double-buffer tick (`domain.ecs.tick/run-parallel`) and every owner system are
built and tested. **Not yet the live default:** `phase0/tick-world` still runs
the sequential pipeline by default; set `:phase0/parallel? true` to run the
double-buffer path. The one open item is *content* tuning, not the substrate —
the parallel model's accretion lags condensation, so it doesn't yet form a star
(see §10). §4 below is the **as-built** ownership; §3 the as-built tick.
**Date:** 2026-06-26
**Scope:** the per-tick update discipline for the single ECS substrate. Phases are content
layers on top of this; this document is the substrate. See `[[single-ecs-substrate]]`.

---

## 0. The one sentence

Every tick, freeze the world into an immutable snapshot; run every system concurrently
on its own thread reading **only** from that snapshot and writing **only** to component
types it exclusively owns; at end-of-tick, fold the disjoint writes into the next world,
apply discrete events serially, and swap. Order between systems cannot matter because no
system observes another's same-tick writes.

---

## 1. The problem this fixes

Today `domain.ecs.core/tick` is:

```clojure
(defn tick [world system-fns]
  (-> (reduce run-system world system-fns) advance-tick))   ;; Gauss–Seidel
```

`reduce` threads one world through the systems in sequence, so system *k* sees the
in-progress writes of systems *0..k-1* **this same tick**. Consequences we are now paying:

1. **Order dependence.** The hand-curated 12-element `physics-systems` vector is load-bearing.
   The comment in `phase0.clj:330` is a *correctness argument for an ordering*. Every system
   added is another ordering edge to reason about. Coupling grows combinatorially.
2. **No parallelism.** A sequential fold cannot use more than one core for the system layer.
   Barnes–Hut gravity (the dominant cost) blocks everything behind it.
3. **Hidden multi-writer conflicts.** Because order resolves them implicitly, we never had to
   confront that `position` has 3 writers, `pressure` 4, `temperature` 3, `radius` 3. These
   are real shared-state hazards masked by sequencing.

The double buffer fixes all three at once because they are the same property —
*no system reads another system's uncommitted state* — seen from three angles.

We are building a game. We **accept** the cost (§7) and take the simple, fast, order-free design.

---

## 2. The model

Three rules. They compose into the whole architecture.

### Rule 1 — Read from the frozen snapshot, write to a private buffer (Jacobi update)

A tick reads tick *N* and produces tick *N+1*. Within the tick, the snapshot of *N* is
immutable and shared by all systems. No system mutates it; each emits its writes into a
private write-set. This is a **Jacobi** iteration (read-old / write-new), not Gauss–Seidel
(read-and-write-in-place). Permuting the system list yields bit-identical results.

### Rule 2 — Single writer per component type

**Every component type is written by exactly one system.** This is the load-bearing invariant.
Once it holds, write-sets are provably disjoint, so:

- the end-of-tick fold is a conflict-free merge (no policy, no last-writer-wins), and
- each system is data-race-free by construction → **one thread per system, no locks.**

The ownership table (§4) is therefore not documentation — it is an enforced invariant,
validated at startup and asserted in tests. A second writer is a build failure, not a bug.

### Rule 3 — Contended values are decomposed, never co-written

When several systems legitimately influence one value, they do **not** share a writer. The
value is split. There are exactly four shapes a contended value can take:

| Shape | Mechanism | Example |
|---|---|---|
| **Accumulator** | One *integrator* owns the absolute value. Each influencer owns a distinct **contribution** component. The integrator reads the union and **sums** them (commutative → order-free). | velocity ← Σ accelerations; temperature ← Σ heat rates; B ← Σ dB/dt; L ← Σ torques |
| **Derived** | One owner computes the value as a pure function of other components. Nobody else writes it. | pressure = EOS(ρ, T); spin ω = L / I; radius = geometry(state, m, ρ) |
| **State machine** | One owner holds the value; influencers emit **signal** components; the owner applies prioritized transitions. | matter-state ← {jeans-unstable?, ignition-ready?, mass-bin} |
| **Discrete event** | Not a parallel system at all. An event handler applied **serially at the barrier** (§6), recorded in the ledger. May write anything because it runs outside the fan-out. | collision/merge |

This is the generalization of "velocity is its own integrator system, and everything that
wants to push on it emits a force." Accumulators handle additive influence; derivation handles
functional influence; the state machine handles discrete transitions; events handle
ledger-recorded discontinuities.

## 3. The tick algorithm

```clojure
;; domain.ecs.core (new)

(defn tick
  "world_N -> world_{N+1}. Jacobi double-buffer. Order-independent."
  [snapshot registry]                       ;; registry := [{:id :reads :writes :fn} ...]
  (let [;; 1. FAN OUT — every system on its own thread, reading the SAME frozen snapshot.
        futs   (mapv (fn [{:keys [fn] :as sys}]
                       [sys (future (fn snapshot))])    ;; => write-set (entity->{ctype val})
                     registry)
        ;; 2. BARRIER — await all. Each write-set touches only that system's owned ctypes.
        wsets  (mapv (fn [[sys f]] [sys @f]) futs)
        ;; 3. FOLD — merge disjoint write-sets into a fresh next world. No conflicts possible.
        world' (reduce (fn [w [_sys ws]] (apply-write-set w ws)) snapshot wsets)
        ;; 4. EVENTS — discrete handlers applied serially, recorded in the ledger (§6).
        world' (apply-events world' (collected-events wsets))
        ;; 5. GLOBAL REDUCTIONS — frame recenter etc. (§5.position).
        world' (recenter world')]
    ;; 6. SWAP — world' becomes the read-snapshot for tick N+1.
    (advance-tick world')))
```

- A **write-set** is `{entity-id {ctype value}}` restricted to the system's owned ctypes;
  `:remove` sentinels express "this entity no longer has my component" (single owner ⇒ the
  owner is responsible for clearing its own stale entries).
- `future` per system is the v1 thread model: pure reads from an immutable persistent map are
  trivially thread-safe, and the only synchronization is the barrier at step 2. Replace with a
  fixed `ExecutorService` sized to cores once profiled; the contract (frozen-read, private-write,
  barrier) is unchanged. The existing `domain.ecs.parallel/par-mapv` stays as the *intra-system*
  per-entity parallelism (e.g. inside Barnes–Hut); this spec adds *inter-system* parallelism on
  top.

### Determinism

Parallel fan-out does **not** threaten determinism: each integrator sums its contribution inputs
in a **fixed order** (sorted by entity id, then by contribution ctype). Floating-point summation
is therefore reproducible regardless of thread scheduling. The fold order over write-sets is
irrelevant because the sets are disjoint. Event application order is fixed (sorted by ledger
sequence). Same snapshot + same registry ⇒ bit-identical next world.

## 4. Ownership table (the invariant — AS BUILT)

Every component has exactly one fan-out writer. Enforced at boot by
`registry/assert-single-writer!` and in `architecture_test`. `*` marks systems
introduced or split during the migration. This table is the source of truth in
prose; `domain.ecs.registry/systems` is the source of truth in code.

### The force accumulator (the one true accumulator)

| Component | Sole owner | Notes |
|---|---|---|
| `position`, `velocity` | **Motion*** | symplectic step `v+=a·dt; x+=v·dt`; SUMS the accel.* below |
| `accel.gravity` | **Gravity*** | Barnes–Hut, split out of the old orbital system |
| `accel.pressure` | **Hydro** | SPH pressure-gradient |
| `accel.lorentz` | **EM-lorentz*** | (∇×B)×B / (μ₀ρ) |

### Derived state (pure function of other components — no accumulation)

| Component | Sole owner | Relationship |
|---|---|---|
| `radius`, `density`, `oblateness`, `rotation-axis` | **Structure*** | one geometric fact; gas SPH / solid material density / KH oblate contraction |
| `pressure` | **EOS*** | P = ρ k_B T / m_H |
| `temperature` | **Thermal** | cores: virial T = G M m_H/(k_B R) (a derivation from mass+radius); solids: radiative; nebula: untouched |
| `spin` | **EM** | ω = L / I(mass, radius) — spin-up emerges as I shrinks |
| `b-field`, `frozen-flux` | **Field*** | conserved flux Φ = B·R² ⇒ B = Φ/R² amplifies as R contracts; + Ohmic decay |
| `angular-momentum` | **EM** | magnetic-braking torque |
| `luminosity` | **Fusion** | from T, P, composition |
| `regime` | **Regime** | dominant-physics tag |
| `accretion-radius` | **Jeans-collapse** | feeding-zone radius |

### State machine

| Component | Sole owner | Inputs (read inline from physics — no signal components) |
|---|---|---|
| `matter-state` | **Classifier*** | Jeans-instability + core-density gate condensation; mass + ignition decide fate |

### Barrier systems (serial, after the fold — exempt from single-writer)

| System | Writes | |
|---|---|---|
| **Collision-detection** | (events) — merge handler despawns + overwrites | discrete events (§6) |
| **Recenter** | `position` | global COM reduction (§5) |

> **The design evolved from the original plan — and this table is the evolution.**
> This spec first proposed accumulator decompositions for temperature (`heat.*`),
> b-field (`dbdt.*`), and rotation (`torque.*`), each feeding an integrator.
> Reading the actual physics showed those quantities are *functionally derivable*,
> not additive: temperature is dominated by the virial relation (a function of
> mass+radius that Structure owns), spin is ω = L/I, flux-freezing is a
> conserved-flux derivation B = Φ/R². So **only FORCE became a true accumulator**;
> the rest are single-owner derivations. No `heat.*` / `dbdt.*` / `torque.*` /
> `signal.*` components were ever created — simpler and exact. `collapse` and
> `density-system` are fully retired from the fan-out. See the formation-physics
> note §7 for the structural reasoning.

## 5. The systems, re-specified (AS BUILT)

The registry is an **unordered set** (`registry/systems`, keyed by `:id`). Order is irrelevant by
Rule 1; the list exists to enumerate threads and validate single-writer. The fan-out has 13 systems
(plus 2 barrier systems). `phase0/physics-systems-parallel` assembles the runnable set: most are
native write-set systems; a few legacy `(fn [world] world')` systems run through the bridge
(`tick/legacy-system`) masked to their owned writes.

**Force emitters + integrator**
1. **Gravity** (native) → `accel.gravity` — Barnes–Hut on its own thread
2. **Hydro** (native, `hydro/pressure-acceleration`) → `accel.pressure`
3. **EM-lorentz** (native, `em/lorentz-acceleration-system`) → `accel.lorentz`
4. **Motion** (native) → `position`, `velocity` — sums the accel.* trio, symplectic step

**Derivers / classifier**
5. **Structure** (native) → `radius`, `density`, `oblateness`, `rotation-axis`
6. **EOS** (native) → `pressure`
7. **Thermal** (native, `stellar/temperature-system`) → `temperature` (virial for cores, radiative for solids)
8. **Field** (native, `em/field-system`) → `b-field`, `frozen-flux`
9. **Classifier** (native) → `matter-state`
10. **Regime** (legacy) → `regime`
11. **Fusion** (legacy, masked) → `luminosity`
12. **Jeans-collapse** (legacy, masked) → `accretion-radius`
13. **EM** (legacy, masked) → `angular-momentum`, `spin`

**Barrier (serial, after the fold)**
- **Collision-detection** → discrete merge events
- **Recenter** → `position` (global COM reduction)

> The original §5 here listed four separate integrators (Thermal/Field/Rotation) fed by
> `heat.*`/`dbdt.*`/`torque.*` contributions. That was simplified to derivations (see §4's note),
> so there is one integrator (Motion) and the rest are derivers. `collapse` and `density-system`
> are retired from the fan-out.

### position — the one global reduction

`position` is owned solely by the **Motion integrator**. The two former co-writers:

- **Collision merge** → discrete event (§6).
- **Recenter (COM frame shift)** → a *global reduction*, not a per-entity system. COM depends on
  all positions+masses, so it cannot be a single-writer emitter without reading the post-fold
  world. Two acceptable forms:
  - **(preferred, stays parallel & order-free):** the Motion integrator subtracts a `frame-offset`
    computed from the **previous snapshot's** COM. One tick stale, physically irrelevant (pure
    Galilean shift), keeps everything in the fan-out.
  - **(fallback):** apply recenter as a deterministic post-fold pass at step 5 of the tick, in the
    same serial slot as event application. Allowed because it runs at the barrier, outside the
    parallel region.

  We take the **preferred** form unless it visibly drifts.

### Mutual dependencies become well-defined

Gas `density` depends on `radius`; gas `radius` depends on `density`. Under Gauss–Seidel this was
an ordering hazard. Under Jacobi it's a clean fixed-point iteration: each reads the other's tick-*N*
value and converges over ticks. Circular reads are *legal and stable* in this model — a real
benefit, not just a tolerated cost.

## 6. Discrete events at the barrier

Collisions/mergers are **not** parallel systems. The **collision-detection** system runs in the
fan-out as a read-only emitter: it reads positions/radii from the snapshot and emits
`:event/collision` records into its write-set's event channel. It writes **no** component state.

At step 4 of the tick, after the fold, events are applied **serially in fixed ledger order** by
their handlers (e.g. `stellar/stellar-merge-handler`), each producing a new world and appending to
the hash-chained ledger (`law.ledger`). Because this is serial and post-fold, handlers may write
any component — they are the sanctioned exception to single-writer, the "discrete, contingent"
half of the event model (`[[phase0-em-layer]]`, and the event-model note: "Position changes are
NOT events. Collisions, deaths, interactions are."). This is exactly the immutability split the
rewindable/ledger design already committed to: **continuous state is reconstructible from a
snapshot + replay; only discrete events are stored.**

## 7. What this costs (accepted)

- **Pipeline latency.** A contribution emitted at tick *N* is integrated at *N+1*; the
  force→accel→velocity→position chain spans a few ticks. At real-time tick rates this is
  physically negligible. We pay it to buy the pure "order never matters" guarantee. We are making
  a game, not proving a thesis — latency is fine.
- **More component types.** Splitting accumulators introduces contribution components
  (`accel.*`, `heat.*`, `dbdt.*`, `torque.*`, `signal.*`). This is the price of single-writer; it
  is also self-documenting (every force is a named, inspectable component).
- **Barrier per tick.** The end-of-tick fold is the one synchronization point. Wall-clock per tick
  ≈ the slowest single system (gravity), not the sum — which is the speedup.

## 8. Non-goals

- Not lock-free *within* a tick beyond the snapshot/private-buffer discipline — we do not need STM
  or atoms; persistent maps + futures + a barrier suffice.
- Not removing the ledger or rewindability — this spec *feeds* them: the swapped-out world is
  discarded from memory and reconstructed on demand from snapshot+replay (`[[single-ecs-substrate]]`,
  rewindable protocol).
- Not changing physics formulas — only *which system owns which write*.

## 9. Migration plan — DONE

All steps landed incrementally, each preserving a green build and the
disjoint-writer assertion. Final state: 10 contended components → **0**.

1. ✅ **Registry + invariant** — `domain.ecs.registry`; `assert-single-writer!`; the
   `architecture_test` baseline shrank to `{}` and now asserts `(empty? conflicts)`.
2. ✅ **Double-buffer tick** — `domain.ecs.tick/run-parallel` + `legacy-system` bridge; behind
   `:phase0/parallel?`.
3. ✅ **Gravity split** — `accel.gravity`; Motion sums `accel.*` (symplectic step).
4. ✅ **Force accumulator** — `accel.pressure` (hydro) + `accel.lorentz` (em); `hydro-accel` retired.
5. ✅ **Derivations** — EOS owns `pressure`; Structure owns `radius`/`density`/`oblateness`/`axis`;
   EM derives `spin` = L/I; Thermal derives core `temperature` = virial; Field derives `b-field`
   from conserved flux. (Replaced the planned heat/dB-dt/torque accumulators — see §4 note.)
6. ✅ **Classifier** — sole writer of `matter-state` (the authentic formation state machine).
7. ✅ **Recenter** — barrier reduction (kept post-fold; the frame-offset variant was unnecessary).
8. ⏳ **Flip the flag** — the substrate is ready, but the live default stays sequential pending §10.

## 10. Go-live status (the one open item)

`phase0/step-physics` runs the double-buffer path when `:phase0/parallel? true`; the default is
sequential. The substrate is complete and correct — but the **parallel model's accretion lags its
condensation**, so it does not yet form a star: at the toy resolution each parcel reaches core
density and condenses *individually* (→ brown dwarf) faster than gravity clusters parcels into a
merging core. The sequential pipeline still forms stars (it merges parcels as gas first), so it
remains the live default. This is **content/physics tuning, not a substrate defect**. Suspects, in
order: the relative (non-absolute) clamp in `hydro/radius-from-density` letting gas radius drift;
the symplectic-Euler + one-tick gravity latency clustering slower than the old leapfrog; the
condensation threshold/timing. Diagnostic: scratchpad `golive.clj`; see `[[ecs-double-buffer-single-writer]]`.
The Gauss–Seidel `physics-systems` vector is **retained** (not deleted) as the live path and the
behavioural reference until the parallel model is tuned to form a star.
