## `law.ledger`: immutable event ledger + Merkle-ish root

**Intent:**

- Represent the ledger as a pure value.
- Append Events immutably.
- Materialize a “snapshot” as “all events up to tick T” (for now).
- Provide a Merkle‑style root that is sensitive to event changes.

This is deliberately simple; you can later evolve `Snapshot` into “materialized component state” once systems come online.

```clojure
(ns law.ledger
  "Immutable append-only event ledger with a Merkle-style root.
   All mutation of world state should be representable as Events
   appended to this structure."
  (:require
    [shape.core :as shape])
  (:import
    (java.util UUID)))

;; --- Ledger and Snapshot ----------------------------------------------------

(defrecord Ledger
  [events]  ;; vector of shape.core/Event, strictly ordered by append
  )

(defn empty-ledger
  "An empty ledger with no events."
  []
  (->Ledger []))

(defn append
  "Append an Event to the ledger. Events are assumed well-formed.
   Returns a new Ledger."
  [^Ledger ledger ^shape.core.Event event]
  (->Ledger (conj (:events ledger) event)))

(defrecord Snapshot
  [tick    ;; logical tick this snapshot corresponds to
   events] ;; vector of Events with timestamp <= tick
  )

(defn materialize-snapshot
  "Materialize a Snapshot from the ledger up to a given tick.
   opts: {:tick int}
   For now, a Snapshot is just the slice of Events with timestamp <= tick."
  [^Ledger ledger {:keys [tick]}]
  (when-not (int? tick)
    (throw (ex-info "materialize-snapshot requires integer :tick"
                    {:kind ::invalid-opts :opts {:tick tick}})))
  (let [events (->> (:events ledger)
                    (filter #(<= (:timestamp ^shape.core.Event %) tick))
                    vec)]
    (->Snapshot tick events)))

;; --- Merkle-ish hashing -----------------------------------------------------
;; We use a simple, deterministic reduction over event data.
;; You can replace this with a real cryptographic hash later.

(defn- event-fingerprint
  "Compute a stable fingerprint for an Event.
   We use clojure.core/hash over a reduced representation."
  [^shape.core.Event e]
  (hash
    {:timestamp (:timestamp e)
     :kind      (:kind e)
     :cause     (:cause e)
     :claims    (map (fn [^shape.core.Claim c]
                       {:shape-id (:shape-id c)
                        :value    (:value c)
                        :context  (:context c)})
                     (:claims e))}))

(defn merkle-root
  "Compute a Merkle-style root hash for the entire ledger.
   Implementation detail: currently a left-fold over event fingerprints.
   Changing any event's content changes the root."
  [^Ledger ledger]
  (reduce
    (fn [acc ^shape.core.Event e]
      (hash [acc (event-fingerprint e)]))
    0
    (:events ledger)))

(defn snapshot-hash
  "Compute a hash of a Snapshot's content.
   Two snapshots with identical tick and events yield the same hash."
  [^Snapshot snapshot]
  (hash
    {:tick   (:tick snapshot)
     :events (map event-fingerprint (:events snapshot))}))
```

Notes:

- `materialize-snapshot` is intentionally minimal. Later, it becomes “world at tick T as component state,” still derived solely from events.
- `merkle-root` and `snapshot-hash` are placeholders for real hashing, but already satisfy the μ‑spec idea: same events ⇒ same root; any change ⇒ different root.[^6_2]

## `domain.system`: component store + event queue + tick skeleton

**Intent:**

- Give you a lawful place to hang ECS semantics:
    - Each System owns a component store (with historical snapshots).
    - Systems consume Events from their queue.
    - Ticks advance time and update the store.
- Keep this minimal and pure: no GL, no IO here. Just data evolution, consistent with your broader ECS direction.[^6_1]


### Component Store

For now, a component store is:

- Fixed `resource-type` (e.g. `:component/position`).
- `window` snapshots retained in history (ring buffer).
- `gap` ticks between stored snapshots.
- `last-tick`.
- `history`: vector of simple snapshots, each:

```clojure
{:tick       int
 :components {entity-id component-map}}
```


```clojure
(ns domain.system
  "System-level ECS orchestration:
   - ComponentStore: ring buffer of component snapshots
   - System: owns a ComponentStore, event queue, contracts
   - queue-event: enqueue events watched by this System
   - tick: advance store and ledger in lockstep
   - observe: read components from historical snapshots."
  (:require
    [shape.core :as shape]
    [law.contract :as contract]
    [law.ledger :as ledger]))

;; --- Component Store --------------------------------------------------------

(defrecord ComponentStore
  [resource-type  ;; keyword describing component kind, e.g. :component/position
   window         ;; number of snapshots to retain
   gap            ;; ticks between stored snapshots (not used heavily yet)
   last-tick      ;; last tick processed, or nil
   history])      ;; vector of {:tick int :components {entity-id component}}
  )

(defn ->component-store
  "Create an empty ComponentStore.
   opts:
   - :resource-type
   - :window (>= 1, default 1)
   - :gap    (>= 1, default 1)"
  [{:keys [resource-type window gap]}]
  (->ComponentStore
    resource-type
    (or window 1)
    (or gap 1)
    nil
    []))

(defn store-window
  [^ComponentStore store]
  (:window store))

(defn store-history
  [^ComponentStore store]
  (:history store))

(defn- current-components
  "Return the component map from the most recent snapshot, or {}."
  [^ComponentStore store]
  (let [history (:history store)]
    (if (seq history)
      (:components (peek history))
      {})))

(defn- append-snapshot
  "Append a snapshot to the store's history respecting the window length."
  [^ComponentStore store snapshot]
  (let [window (:window store)
        history (:history store)
        history' (conj history snapshot)
        trimmed (if (> (count history') window)
                  (subvec history'
                          (- (count history') window))
                  history')]
    (->ComponentStore
      (:resource-type store)
      window
      (:gap store)
      (:tick snapshot)
      trimmed)))
```


### System record and event queue

Systems own:

- A `ComponentStore`.
- A component `Contract` (what component values must satisfy).
- A `tick-contract` (what counts as a valid tick; keep simple for now).
- A set of event kinds they watch.
- An `event-queue`.
- An `update-fn` (pure; given entity-id + old component, returns new component).

```clojure
(defrecord System
  [id
   component-store     ;; ComponentStore
   component-contract  ;; law.contract/Contract for component values
   tick-contract       ;; law.contract/Contract for tick events/options
   watched-event-kinds ;; vector of keywords
   event-queue         ;; vector of Events
   update-fn])         ;; (fn [system entity-id old-component] new-component)
  )

(defn ->system
  "Construct a System. opts:
   - :id
   - :component-store
   - :component-contract
   - :tick-contract
   - :watched-event-kinds
   - :event-queue
   - :update-fn (optional, defaults to identity for now)"
  [{:keys [id component-store component-contract tick-contract
           watched-event-kinds event-queue update-fn] :as m}]
  (when-not (and id component-store component-contract tick-contract)
    (throw (ex-info "System requires :id, :component-store, :component-contract, :tick-contract"
                    {:kind ::invalid-system :system m})))
  (->System
    id
    component-store
    component-contract
    tick-contract
    (vec watched-event-kinds)
    (vec (or event-queue []))
    (or update-fn
        ;; default: no-op, returns old component unchanged
        (fn [_system _entity-id old-component] old-component))))
```


### Event enqueueing

```clojure
(defn watched-kind?
  [^System sys kind]
  (some #{kind} (:watched-event-kinds sys)))

(defn queue-event
  "If the event's kind is watched by the system, enqueue it.
   Otherwise return system unchanged."
  [^System sys ^shape.core.Event event]
  (if (watched-kind? sys (:kind event))
    (update sys :event-queue conj event)
    sys))
```


### Tick semantics (minimal)

`tick`:

- Derives `next-tick`.
- Validates tick options against `tick-contract` (for now, we only pass `{:tick next-tick}`).
- Folds over `event-queue`, projecting component changes.
- Applies `update-fn` per entity as a second pass.
- Appends a new component snapshot to the `ComponentStore`.
- Returns `{ :system updated-system, :ledger updated-ledger }`.

This keeps everything pure: the only “mutation” is new values returned.

```clojure
(defn- apply-events-to-components
  "Project all queued events into component updates.
   We treat any claim whose shape-id matches the component-contract's shape-id
   and whose context has :entity-id as a component update."
  [^System sys components events]
  (let [shape-id (:shape-id ^law.contract.Contract (:component-contract sys))]
    (reduce
      (fn [acc ^shape.core.Event e]
        (reduce
          (fn [acc' ^shape.core.Claim c]
            (if (and (= shape-id (:shape-id c))
                     (some? (get-in c [:context :entity-id])))
              (let [entity-id (get-in c [:context :entity-id])]
                (assoc acc' entity-id {:value (:value c)}))
              acc'))
          acc
          (:claims e)))
      components
      events)))

(defn- second-pass-update
  "Run the system's update-fn over all entities' components."
  [^System sys components]
  (let [update-fn (:update-fn sys)]
    (reduce-kv
      (fn [m entity-id component]
        (assoc m entity-id
                  (update-fn sys entity-id component)))
      {}
      components)))

(defn- append-component-events
  "Given old-components and new-components at tick, generate Events describing
   changes and append them to the ledger."
  [^ledger.Ledger led tick components]
  ;; For now we emit a single event per entity; later you can compress/batch.
  (reduce-kv
    (fn [l entity-id {:keys [value] :as component}]
      (let [e (shape/->event
                {:timestamp tick
                 :kind      :component-updated
                 :cause     :system
                 :claims    [(shape/->claim
                               {:id          (shape/new-claim-id)
                                :shape-id    (:shape-id component) ;; optional later
                                :value       value
                                :context     {:tick tick
                                              :entity-id entity-id}
                                :asserted-by (:id sys)})]})]
        (ledger/append l e)))
    led
    components))

(defn tick
  "Advance the system and ledger by one tick.
   Arity-2: [system ledger] -> {:system system' :ledger ledger'}
   Arity-1: [{:keys [system ledger]}] -> same.

   Semantics:
   - next-tick = (inc last-tick) or 1 if nil
   - validate {:tick next-tick} against tick-contract
   - apply queued events to component map
   - run update-fn per entity
   - append a new snapshot to component-store's history
   - clear event-queue
   - (optional) append component-changes as events to ledger (stubbed for now)"
  ([^System sys ^ledger.Ledger led]
   (let [store           (:component-store sys)
         last-tick       (:last-tick ^ComponentStore store)
         next-tick       (if (nil? last-tick) 1 (inc last-tick))
         ;; TODO: use a real tick event / options here
         tick-claim      (shape/->claim
                           {:id          (shape/new-claim-id)
                            :shape-id    (:shape-id (:tick-contract sys))
                            :value       {:tick next-tick}
                            :context     {}
                            :asserted-by (:id sys)})
         tick-result     (contract/validate (:tick-contract sys) tick-claim)]
     ;; If tick is invalid, we might want to record a violation event;
     ;; for μ purposes, we throw.
     (when (not= contract/ok tick-result)
       (throw (ex-info "Tick contract violated"
                       {:kind    ::tick-contract-violation
                        :issues  (:issues tick-result)
                        :tick    next-tick})))
     (let [components0 (current-components store)
           ;; project queued events
           components1 (apply-events-to-components sys components0 (:event-queue sys))
           ;; run per-entity update
           components2 (second-pass-update sys components1)
           snapshot    {:tick       next-tick
                        :components components2}
           store'      (append-snapshot store snapshot)
           sys'        (-> sys
                           (assoc :component-store store')
                           (assoc :event-queue []))
           ;; For now we leave ledger unchanged; component changes
           ;; are already represented by incoming events.
           led'        led]
       {:system sys'
        :ledger led'})))
  ([{:keys [system ledger]}]
   (tick system ledger)))
```

**Important note:**

- `append-component-events` is stubbed out / unused above; I included it as a placeholder for the “Systems generate new Events for component changes” path. Right now, `tick` treats the ledger as the source of truth and not as a sink for new component Events. You can flip that once you’re ready to go full event‑sourced on intra‑system updates.[^6_2]

**Observe:** simple read into the history ring buffer.

```clojure
(defn observe
  "Given a system, entity-id, and optional tick-offset (0 = latest),
   retrieve the component record for that entity at that historical tick.
   Returns nil if not present or out of range."
  ([^System sys entity-id]
   (observe sys entity-id 0))
  ([^System sys entity-id tick-offset]
   (let [store   (:component-store sys)
         history (:history ^ComponentStore store)
         idx     (- (count history) 1 tick-offset)]
     (when (and (>= idx 0) (< idx (count history)))
       (let [snapshot (nth history idx)]
         (get-in snapshot [:components entity-id])))))
```
