# Proposed host input cost comparison — not executed

The changed hot path is host context projection, guarded queue consumption and manual Sculpt attention preparation. `bin/bench :phase0` times domain work and does not exercise this boundary; a passing domain benchmark would not qualify it.

Use one fresh JVM per revision, sequentially, with `JAVA_OPTS=-Xms256m -Xmx2g`, inherited JVM options removed, no native window, no service or renderer, and an absolute 180-second process budget including bounded cleanup. Baseline is committed `f0c4710a8306aa634af9f49859c11451515ed912`; candidate is the exact source pins in `VERDICT.json`. Root must first release the resource window. Pin the adapter/fixture/deps and both source sets; retain command, runtime, compact process identity, start/end, full output, exit/reap and external load observations. A timeout is a failed measurement, not permission to shorten settings or silently repeat.

A small adapter should reuse the existing Criterium 0.4.6 `quick-benchmark*`/`execute-expr` path (see `bench/gates_of_truth/bench.clj:60` and `.ημ/diagnostics/kepler-cost/evidence/kepler.clj:76`). Four cases are enough:

1. Empty queue: actual candidate `iteration-context` and private `drain-intents`; baseline actual two-argument drain.
2. Sixteen legacy intents, using the actual `IntentAtom` and unchanged swap/reset protocol.
3. One paid manual Sculpt action via actual private `dispatch-palette-action!`: baseline legacy submission versus candidate explicit contextual capability, then their actual drain.
4. Eight paid manual Sculpt actions as a finite burst through those same paths.

Every invocation begins from the same immutable fixture and fixed config, with a freshly empty queue and the original fixture still published. Queue production and consumption are both timed and disclosed; do not call this drain-only cost. Candidate context is computed once per invocation. Use the existing committed-planet/physical-Spark test fixture, set sufficient Resonance and align its initial focus to physical position plus the same offset so the comparable case has exact semantic equality. Capture that fixture once as EDN, prove exact round trip, and consume identical bytes in both JVMs. Before timing each case, assert exact resulting world equality (paid count/cost, focus/anchor, physical columns and FIFO trace), original publication unchanged and queue empty. If equality fails, stop and report; do not silently alter the fixture or normalize differences. The separately tested stale-anchor scenario intentionally differs and is not a timing-equivalence oracle. No invalid/error logging is timed.

For each case retain default quick-benchmark warm-up/options and raw samples/intervals. After warm-up, retain 20 current-thread CPU/allocation batches of 1000 invocations through `execute-expr`, consuming its output, with identical sink/counter overhead. Require supported/enabled counters. Report raw samples, median, min/max, quartiles and MAD; report Criterium wall intervals separately. Do not remove outliers or infer significance from a single pair. Serialize only the known Criterium OutlierCount record as its explicit type plus every field, following the existing adapter; never dump environment/JVM argument metadata or weaken fixture equality.

This characterizes added boundary cost on a compact fixed world. It does not time the unchanged post-drain focus refresh, full integrator, parallel futures, render/GL/input latency, native play or tick throughput. A one-pair result can identify substantial overhead or establish scale; overlapping wall intervals remain inconclusive. No automatic reverse pair or production optimization is authorized by this plan. If the common queue/setup cost obscures a material conclusion, report that limitation rather than fabricate a host throughput claim.
