# Passive native trail observation

Authorized under existing InProgress5 body-trails-ringbuffer. This diagnostic
runs only on the owned hardware PID4070721, process-start3869117, :0/7896,
world atom275227937 and native window129843170276688. No camera/follow, desktop
input, unlock, selection, HUD/magnetic visibility, body/time/history injection,
world tick, fixture, lifecycle restart or extra context is requested.

The temporary bodies-fn observer calls the saved production function once and
returns its exact result unchanged. It retains the latest exact projection input
world on the owning render thread. The actual render-scene facade observer calls
its saved original once with unchanged arguments/results; original exceptions
still propagate. Diagnostic exceptions are recorded and cause restoration, not
production UI failure. A frame already in flight at installation may be skipped
and counted as unpaired. Current bodies retain their existing fields and HUD.

The first usable frame fixes one naturally present star and planet with at least
two nonzero actual trail segments. Three full GL_BACK frames maximum are taken
at the initial projection simulation time, half a 6.3e11-second trail horizon
later, and one horizon later. A 60-second wall deadline closes on the next frame;
an operator verification/restorer is required if rendering stops before then.
Do not advance time artificially or substitute another target. Missing time,
geometry, pixel readability or a vanished target remains an incomplete result.

Actual :trail/entity-tagged scene endpoints must equal a fresh call to the
production project-trails function on that exact input world. Capture records
include the selected actual histories, endpoint alpha/screen projection,
production budget and all-scene line/shape counts. The published world read after
the scene is a separately labeled observation. Color alone is not attribution.

GL_BACK readback follows the reviewed fresh-game observer: owned thread/current
context, default read FBO and ordinary pack state are required; read buffer is
restored in finally; full scene/HUD pixels are retained unedited. Bounded glGetError
samples consume flags and cannot restore them. Readback/PNG/projection overhead
and concurrent qualification work preclude FPS/performance conclusions.

Restoration removes only the diagnostic scene root and bodies-fn setting,
including exact original key presence/value, preserving unrelated current config.
It does not rewind the naturally evolving world. No manual flight/commitment/Gate
claim is possible from this passive view. Numeric alpha alone does not establish
visible star/planet fading. Parent owns commits and canonical board comments.
